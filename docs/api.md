### API для управления данными о туристических поездках

Необходимые для проекта данные хранятся на локальном json-server.
Для работы с json-server необходимо его установить:

  ```
  npm install json-server
  ```
  <https://www.npmjs.com/package/json-server>
  <https://github.com/typicode/json-server/tree/v0>

В файле package.json в разделе "scripts" необходимо добавить строку:

  ```
  "server": "json-server --watch db.json --static ./public --port 3000"
  ```
  - --watch db.json указывает на отслеживаемый файл базы данных;
  - --static ./public указывает на статические данные, в нашем случае на каталог с изображениями, используемыми в проекте;
  - --port 3000 - указывает на используемый порт.

Также необходимо установить пакет npm-run-all, используемый для обеспечения параллельного или последовательного запуска npm скриптов.

  ```
  npm install npm-run-all --save-dev
  ```
  <https://www.npmjs.com/package/npm-run-all>
  <https://github.com/mysticatea/npm-run-all/blob/master/docs/npm-run-all.md>

В файле package.json в разделе "scripts" необходимо добавить строку:

  ```
  "dev": "npm-run-all --parallel server wait-for-server"
  ```    

Для обеспчения доступности данных используется пакет wait-on: до запуска скрипта для работы с данными, необходимо дождаться запуска сервера.

Установка wait-on:

  ```
  npm install wait-on
  ```
  <https://www.npmjs.com/package/wait-on>
  <https://github.com/jeffbski/wait-on/blob/master/README.md>

В файле package.json в разделе "scripts" необходимо добавить строку:

  ```
  "wait-for-server": "wait-on http://localhost:3000 && npm run script"
  ```    
Для подключения модуля с функциями управления данными надо добавить в раздел "scripts" файла package.json следующую строку:

  ```
  "script": "node server/script.js"
  ```

##### **Конечные точки:**

1.  **/data**
    **Описание**: содержит информацию о:
    - локациях: наименование, описание и структуру поездок в пределах каждой локации;
    - турах, доступных в каждой локации: наименование, описание, программу, стоимость, фото;
    - перечень базовых услуг, доступных в каждом туре;
    - фото популярных направлений.

    **Структра данных**:
    - *titleSection1* - заголовок главного раздела.
    - *dataSection1_2* - данные о локациях, турах и программах.
      - *tourId* - идентификтаор локации.
      - *tourName* - наименование локации.
      - *titleSection2* - заголовок раздела, содержащего общую структуру туров локации.
      - *subtitleSection2* - подзаголовок раздела, содержащего общую структуру туров локации.
      - *tourStructure* - описание общей структуры туров локации.
      - *tourDescription* - описание локации.
      - *tourDirections* - туры локации.
          - *dirId* - идентификатор тура.
          - *dirName* - наименование тура.
          - *dirPrice* - стоимость тура.
          - *dirDescription* - описание тура.
          - *dirProgram* - программа тура.
              - *id* - идентификатор мероприятия.
              - *name* - наименование мероприятия.
          - *image* - фото с мероприятий тура.
    - *dataSection3* - данные о базовом наборе услуг для каждого тура.          
      - *titleSection3* - заголовок раздела, содержащего информацию о базовом наборе услуг для каждого тура.
      - *subtitleSection3* - подзаголовок раздела, содержащего информацию о базовом наборе услуг для каждого тура.
      - *baseServices* - данные об услугах из базового, гарантированного набора.
          - *id* - идентификатор услуги.
          - *name* - наименование услуги.
          - *description* - описание услуги.
    - *dataSection4* - данные о популярных турах.
      - *titleSection4* - заголовок раздела, содержащего информацию о популярных турах.
      - *subtitleSection4* - подзаголовок раздела, содержащего информацию о популярных турах.

2. **/blogs**
    **Описание**: содержит отзывы путешественников и фото посещаемых локаций.
    **Структра данных**:
    - *titleBlogs* - заголовок раздела, содержащего отзывы путешественников.
    - *subtitleBlogs* - подзаголовок раздела, содержащего отзывы путешественников.
    - *dataBlogs* - данные с отзывами путешественников.
      - *blogId* - идентификатор отзыва.
      - *blogName* - идентификатор тура, по которому оставлен отзыв.
      - *blogDate* - дата формирования отзыва.
      - *blogDate* - текст отзыва.
      - *image* - фото.

#####  Методы:

Функция api, находящаяся в модуле server/api.js, предоставляет удобный способ работы с методами запросов API.

Для работы с данными необходимо использовать утилитарные функции, находящиеся в модуле server/script.js.

Модуль server/constants.js содержит переменные, в которых хранятся URL конечных точек и наименования методов API.

1. **GET**: получить все данные по заданой конечной точке.

    Параметры: 
     - endpoint (string): URL конечной точки.

    Пример запроса: 
    ```
    http://localhost:3000/data
    ```
    или 
    ```
    http://localhost:3000/blogs
    ```

    С помощью утилитарной функции:

    ```
    const data = await getData(SERVER_URL_DATA);
    ```
    Формат ответа:
      - в случае успешного выполнения запроса данные возвращаются в формате JSON, структура возвращаемых данных зависит от указанной конечной точки (см. в разделе "Конечные точки");
      - в случае ошибки запроса возвращается объект, содержащий информацию о произошедшей ошибке:

    ```
    {
      error: true,
      message: 'Источник данных не определен' 
    }
    ```

##### **Описание функции генерирования уникального id**

Функция genUniqeId(n) создаёт случайный идентификатор из n символов, используя шаблон (где некоторые позиции будут заменены случайными значениями) и криптографически безопасные случайные числа.

1. Код ([1e7] + -1e3 + -4e3 + -8e3 + -1e11) формирует строку "10000000-1000-4000-8000-100000000000" (36 символов, с дефисами)
https://ru.wikipedia.org/wiki/UUID

2. Метод .replace(/[018]/g, (c) => ...) ищет в строке все 0, 1 и 8 и заменяет их на случайные шестнадцатеричные цифры (0–9, a–f). Для случайности используем crypto.getRandomValues, который даёт число от 0 до 255.

3. С помощью побитовых операций число превращается в подходящий символ. Для 0 и 1 выбирается диапазон от 0 до f, для 8 — выбираем из 8, 9, а, b (необходимо для стандарта UUID)
https://learn.javascript.ru/bitwise-operators

4. Получившуюся строку обрезаем до n символов (тут есть проблема с "уникальностью" если n слишком маленькое число).

ПРИМЕР:
Допустим, мы вызываем genUniqeId(8):

* Шаблон: "10000000-1000-4000-8000-100000000000".
* replace заменяет все 0, 1, 8 на случайные шестнадцатеричные символы:
Например, 0 может стать a, 1 → b, 8 → f.
Возможный результат: "a23b4567-cdef-4abc-d123-456789abcdef".
slice(0, 8) возвращает: "a23b4567".
* Каждый вызов даёт новый ID, так как crypto.getRandomValues генерирует разные числа.
